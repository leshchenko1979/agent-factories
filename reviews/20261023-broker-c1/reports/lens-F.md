### 1. HIGH — двойная отправка контрагенту при сбое моста

`reestr_send.py:60`

```python
    except Exception:  # noqa: BLE001
        return None, ""
```

Сверка после падения (`reestr_send.py:196`) читает этот `(None, "")` как факт «сообщения в чате нет» и печатает `отметка была незакрыта, сообщения в чате нет — отправляю заново`, после чего отправляет текст повторно. Любой сбой моста (таймаут 60 с, нечитаемый JSON, отсутствующий `tg-mcp-call`) неотличим от «сообщение не дошло». Сценарий: сообщение доставлено, ответ моста не распарсился → владелец получает второе такое же письмо контрагенту. Здесь молчаливый `except` не просто глотает ошибку — он превращает её в необратимое внешнее действие.

**Патч:** вернуть трёхзначный результат `(mid, text, ok)`; при `ok is False` — `print("отказ: чат не прочитан, сверка невозможна, отправка отменена", file=sys.stderr); return 2`.

### 2. HIGH — миграция пишет единственный источник правды неатомарно

`migrate_reestr_v2.py:302`

```python
    path.write_text(text, encoding="utf-8")
```

Прямое противоречие докстрингу `reestr_core.save_atomic` («Прямая запись в реестр запрещена: обрыв на середине оставил бы битый YAML, а это единственное место, где живёт состояние») и шапке модуля («скрипты реестр не читают и не пишут сами — только через этот модуль»). Обрыв посреди `write_text` оставляет усечённый `reestr.yaml`; проверка `yaml.safe_load` на строке 303 читает уже испорченный файл и падает трейсбеком. Дополнительно: `yaml.safe_load` без проверки типа → на пустом файле `data.get` даёт `AttributeError` вместо отказа.

**Патч:** `core.save_atomic(new, path)`; перед этим `if not isinstance(data, dict): print(..., file=sys.stderr); return 1`.

### 3. HIGH — read-modify-write без блокировки

`reestr_core.py:215` (`save_atomic`) и `reestr_touch.py:1005` (чтение до правки)

```python
def save_atomic(data: dict, path: Path | None = None) -> None:
```

`grep -rn "flock\|fcntl\|O_EXCL"` по всем шести файлам — **ноль совпадений**. `save_atomic` атомарен только на уровне отдельной записи (temp + `os.replace` + `fsync` + перечитывание — это сделано правильно), но цикл «прочитать → изменить в памяти → записать» ничем не защищён: два одновременных `reestr_touch.py` дают потерянное обновление — второй затирает первый целиком, вместе с его записью в историю. Это не гипотеза: во время аудита в репозитории работала другая сессия — файл был грязным в 10:14:30 UTC и через две минуты закоммичен (`eb4d425`, `22c8412`). Плюс ежедневный крон в 10:00 МСК идёт ровно в часы ручной работы.

**Патч:** в `save_atomic` — `fcntl.flock(LOCK_EX)` на `<path>.lock` вокруг всего read-modify-write (блокировку брать в `main()` до `core.load`, отпускать после `save_atomic`).

### 4. MEDIUM — все отказы схлопнуты в один код

Замеры: битый YAML → lint rc=1, due rc=1, touch rc=1; неизвестное событие → touch rc=1; `--today 2026-13-45` → due rc=1; `--send` без текста → rc=1. Контракт «разные отказы — разные ненулевые коды» не выполнен: инфраструктурный отказ (реестр не читается) и отказ валидации (событие не из словаря) неразличимы, хотя первый требует вмешательства человека, а второй — исправления аргумента. `reestr_lint.py:325` и `:335` — обе ветки `return 1`.

**Патч:** ввести коды: 2 — реестр не читается/не пишется, 3 — отказ валидации (событие, поле, дата), 4 — внешний мост. В `reestr_touch.main` — `return 2` для `OSError`/`yaml.YAMLError`, `return 3` для `TouchError`.

### 5. MEDIUM — «ничего не записано» возвращает 0

`reestr_touch.py:1029`

Проверено: повторный `--message-id 999999` печатает `повтор отброшен` и возвращает **rc=0** — неотличимо от реальной записи. ### 6. MEDIUM — гейт пустого дня сломан хвостовым `git status`

Фактический `trigger_cmd` джоба `broker-requests-daily` (`trigger_on=non_empty`) заканчивается:

```sh
; git status --porcelain -- projects/Брокерские-запросы/reestr.yaml
```

Прогон сегодня: обход дал **пустой** список (пустой день), но выход команды — 163 байта ` M "projects/\320\221.../reestr.yaml"`. Гейт «непустой stdout = есть работа» срабатывает, агент получает в качестве триггера строку git-статуса с экранированной кириллицей, а не список сроков. Второй эффект: `git status` возвращает 0 всегда, поэтому rc цепочки не несёт ничего — при `set -e`-семантике это скрыло бы падение линтера. Заодно `date +%u` берёт пояс хоста (UTC), а не МСК.

**Патч:** убрать `git status` из `trigger_cmd` (коммит реестра — дело прогона, не гейта); `set -euo pipefail`; `TZ=Europe/Moscow date +%u`.
