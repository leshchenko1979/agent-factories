## Дисциплина доказательств (обязательна)

1. **Цитата или «находки нет».** Каждая находка несёт `файл:строка` и дословный фрагмент. Формулировка без цитаты — гипотеза, в отчёт не идёт.
2. **Отрицательный вывод несёт команду** и область поиска: `grep -rn "…" ~/redevest-ai | wc -l` → 0.
3. **Мерка перед вердиктом.** Прежде чем предлагать слить/разрезать/удалить — `grep -rn` по всем местам, которые на находку ссылаются. Правка по устаревшему снимку — отдельный класс ошибок.
4. **Не выдумывать дефекты.** Пустой прогон — законный результат: «линза X: находок нет, проверено то-то, команда такая».
5. **Не менять файлы.** Аудитор только читает и возвращает текст. Никаких правок, коммитов, отправок.

## Формат отчёта аудитора

```
## Линза <буква> — <название>

### Находки

1. **<краткая суть>** · `файл:строка`
   цитата: «…»
   почему дефект: <одно-два предложения>
   действие: <что сделать>

### Отрицательные выводы
- <что проверено и не нашлось> · команда: `…` → 0

### Предложения владельцу (требуют решения, не правки)
- …
```

Сортировка находок — по убыванию серьёзности. Максимум 12 находок на линзу; если больше — 12 самых тяжёлых и строка «ещё N однотипных, класс …».

## Что считается дефектом, а что нет

- **Дефект:** правило расходится с диском; шаг процедуры невыполним; скрипт делает не то, что обещает скилл; два места говорят разное; норма без проверяемого итога; запрет, который нечем проверить.
- **Не дефект:** стиль, длина сама по себе, отсутствие единого шаблона у разных по природе скиллов, исторические записи в `log.md`, решения владельца, зафиксированные в §11 плана (их можно оспаривать только как «предложение владельцу»).
