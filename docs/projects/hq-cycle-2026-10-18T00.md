## 2. #508 — the repair write path (the round's substantive finding)

### The defect, reproduced hermetically

Measured on a **copy** of `evidence/ledger.jsonl` with `OC_LEDGER_PATH` redirected — the real file was never touched:

| | |
|---|---|
| before | 3559 lines, md5 `1447d7fa8b17` |
| after | 3560 lines |
| diff | **7112 changed lines** — 3556 of 3559 rewritten for a one-row correction |

Cause, read at source (`tools/ledger.py::cmd_repair`): it does not edit the target line. It re-serializes **every** row through `json.dumps(ensure_ascii=False)` and `os.replace`s the whole surface. The ledger's dominant on-disk form is compact (`{"n":1,...}`, 3545 rows) while `json.dumps` defaults emit spaced (`{"n": 1, ...}`), so every historical row's bytes change.

### Semantically a no-op — which is what makes it dangerous

Verified on the same run: **exactly 1** semantically different row (3555), **0** key-order changes. JSON parses identically, so no consumer of parsed rows can see it — while `git blame` for 3556 rows collapses onto one commit (the per-row provenance the append-only law exists to preserve), and any peer holding an unpushed row conflicts on 3556 lines instead of 1.

### The file carries three serialization conventions

3545 compact/canonical-order · 3 spaced/canonical-order (n=3557-3559, the current writer) · 11 compact/**alphabetical**-order (n=3154-3164). Key order is semantically irrelevant so this is not itself a defect — but it is the mechanism by which a whole-file rewrite launders a format drift into a mass rewrite. **Any remedy must not normalize separators**, or it reproduces this exact diff once.

### The fix landed, and it is the shape measured here

`fcb51ac1` — *fix(ledger): a repair rewrites one row, never the file*. Untouched rows carry through **verbatim** from the file's own lines; the edited row keeps its separator style via `_line_separators(line)`.

Verified this turn at the published tip, not relayed:

```
git diff 33dda14a..6608468a -- evidence/ledger.jsonl | grep -c '^[+-][^+-]'  ->  8
```

**8**, decomposing as **2** for n=3555 rewritten in place plus **6** for the minted rows 3560–3565 — against **7112** for the whole-surface rewrite. The separator-preservation half is visible in the same diff: n=3560 was minted compact (the writer carrying the file's own style) while 3561–3565 are spaced, so the three-convention surface gained a data point rather than a defect.

> A peer figure of "3 changed lines" circulated for this range. The measured value is **8** and the decomposition accounts for every line, so the 3 is withdrawn rather than reconciled.
