## Consulting Advisories (prioritised)

### 🔴 1. InferHub Watch — restore the self-audit pacemaker (band loss)
- **Symptom:** `tools/audit.py` → *DEGRADED (FAIL) — Cadence: MISSED, last run 68.0 h ago*;
  `evidence/scores/` holds only `2026-09-14.md`.
- **Mechanism:** the self-audit has no pacemaker. Every other recurring process here is
  cron-driven; the audit is invoked by hand, so it stops the moment nobody asks (P28).
- **Fix:** declare a thin daily pacemaker waking the HQ session UUID to run
  `tools/audit.py` and write `evidence/scores/<date>-self-audit.md`, mirroring
  `infra-surveys-daily` / `miidas-hq-daily-trigger`.
- **Expected impact:** A2 2 → 3, and it is the precondition for Stability to become measurable.

### 🔴 2. InferHub Watch — create `evidence/rework.md`
- **Symptom:** Stability's rework rate is uncomputable; `evidence/rework.md` does not exist.
- **Mechanism:** the factory records failures in the skill's improvement ledger, which is a
  process log, not a defect ledger with a `Prevented by` column.
- **Fix:** adopt the template rework schema and gate it with `tests/test_rework.py`.
  Start with today's `#79` (CI dependency step lost in the Pages decommission) — root cause
  and preventative step are already documented in the cycle record.
- **Expected impact:** O2 3 → 4 and S3 2 → 3.

### 🟠 3. AI AntiSpam — adopt the Minimal 2-Process Core Kit
- **Symptom:** D3 1/4; blocked at the consulting gate; A1 1/4.
- **Mechanism:** no ledger, no audit kit, no ontology gate — no surface on which a
  zero-touch ratio or a rework rate could ever be computed.
- **Fix:** port `tools/ledger.py`, `tools/audit.py`, `tests/test_ontology.py` and
  `tests/test_rework.py` from `TEMPLATE/`; write `docs/processes.md` from the existing
  sweep skill.
- **Expected impact:** unblocks consulting; +8 to +10 points.

### 🟠 4. Miidas + Infra Factory — document the methodology core
- **Symptom:** both dropped D3 to 2/4; neither repo has `docs/methodology/`.
- **Mechanism:** the counters (amnesia, concurrency, locking, receipts) and the
  harness/surface bindings are *implemented* by the self-audit kit but not *documented*
  where the criterion asks, so a new lane cannot learn them without reading the kit source.
- **Fix:** add `docs/methodology/` with the 5 template modules, adapted — Miidas and Infra
  have working implementations to document, so this is transcription, not invention.
- **Expected impact:** D3 2 → 3 each; restores the gate margin.

### 🟡 5. Miidas — open the work ledger
- **Symptom:** O1 1/4, A1 1/4 — zero task closes recorded.
- **Mechanism:** only the self-audit writes to the ledger; ordinary work is not intaken.
- **Fix:** route the next real task through `tools/ledger.py` intake → claim → close.
- **Expected impact:** the first honest throughput and autonomy measurement.

### 🟡 6. Fleet-wide — cost per successful task
- **Symptom:** fleet mean 1.33/4; only the Meta-factory writes `cost_usd`.
- **Mechanism:** usage is metered per session (OpenCrabs) and per request (InferHub), but no
  factory divides spend by *accepted* tasks.
- **Fix:** extend the template close-row contract to require `cost_usd` and `outcome`, then
  derive cost-per-success in `tools/audit.py` rather than recording it by hand.
- **Expected impact:** the largest single fleet-wide point pool still on the table.

### 🟡 7. Fleet-wide — version every process law
- **Symptom:** 3 of 6 skills carry no `version:` field (`inferhub`, `miidas`,
  `ai-antispam`); the Meta-factory's is `0.1.0` after daily amendment.
- **Mechanism:** without a version there is nothing for a drift check to compare against,
  so a lane running a stale law cannot be detected.
- **Fix:** add `version:` to each skill frontmatter and wire `oc-drift-check`-style
  verification into each factory's audit kit.
- **Expected impact:** L1 2 → 3 or 4 for four factories.

### 🟡 8. Infra Factory — commit the working tree

  `skills/infra-factory/roles/`.
- **Mechanism:** process law and evidence left uncommitted are outside the recoverability
  surface the rubric measures.
- **Fix:** commit the role cards, the audit artifact and the ledger/rework updates.
- **Expected impact:** S2 3 → 4.

## Method notes and limits of this run

- **Resolution.** This was a **single-session survey** of 6 factories — `Q = N_leaf / S`
  well below the 0.50 high-fidelity band defined in §6 of the measurement procedure. It is a
  **sampled audit**: it reads every factory's own audit artifact, ledger, gate suite and law
  file first-hand, and spot-checks one closed chain per factory, but it does not inspect
  every atomic subprocess. **Superficial (Q < 0.20) is the honest label for the per-criterion
  depth on the two largest factories** (OpenCrabs dev, InferHub Watch); their scores should
  be read as calibrated estimates, and a leaf-auditor fan-out is the correct remedy before
  any score here is treated as a gate.
- **What was read live this run:** all six repos at HEAD; six ledgers (`agent-factories` 140
  rows, `opencrabs` workers-ledger 6020 events, `inferhub-watch` 54 rows, `miidas` 8 rows,
  `vds-servers` 20 rows, `ai-antispam` absent); six audit runs; the cron table (27 jobs);
  `smoke-verdicts.log`; four ontology/rework/single-writer gate suites; three skill
  frontmatters; the board state of the Meta-factory repo.
- **Numbers with predicates.** "Rework rate" = rework-log rows ÷ ledger `close` rows, both
  counted this run. "Throughput" = `close` rows in the ledger, plus the last-24 h event
  delta where the ledger carries timestamps. Where a rate's denominator is zero (Miidas) the
  rate is reported as *uncomputable*, never as 0%.
- **Not scored from memory.** Nothing above is carried over from 2026-09-16 except the
  comparison column, which is labelled with its own rubric version.
