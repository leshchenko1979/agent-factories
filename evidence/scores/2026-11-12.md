## Method

**One round, one artifact, one file per run.** The procedure is
`docs/measurement-procedure.md`; this section records only what this round did differently or
what a reader needs in order to reproduce it.

### Instrument

`python3 tools/audit.py --json`, launched `2026-11-12T06:01:13.095699819Z` under
`timeout 7200`, detached with `setsid nohup`. Its JSON is the round's payload; its stderr carries
the scope banner and nothing else — **the audit emits no progress stream and writes only at
exit**, so a reader polling for partial output will see 0 bytes for the whole run.

The audit re-execs itself into a `systemd-run --user --scope` with a 2 560 M ceiling. That
ceiling is derived from a measured peak of 1 265.9 MiB at `2026-11-07T13:36:37Z` over 418 samples.
The scope this round landed in is named in the Executive Summary.

### Exclusivity

**No sample was taken while the audit ran.** Every reading in this artifact is either a file
stat, a `systemctl show`, a SQLite read of a copy, a ledger parse, or a `gh` query — none of them
touches the gate suite. That matters because the §5.2 leg derives time budgets from the audit's
own durations, and a concurrent gate run would inflate them.

**A peer audit was running concurrently**: `audit.py --repo` in `/root/ai-antispam`, pid 551590,
started `05:51:34Z`, in the daemon's own `opencrabs-ops.service` cgroup. It is a different
repository, so it shares the CPU but not the payload — this is a stated limit on the durations
below, not a correction to them.

### What was re-read rather than carried

- Every scorecard cell and all six totals, parsed from the prior artifact's own bytes and re-summed.
- Every member ledger's 7-day window, re-read at `06:05Z` with the file's mtime beside it.
- The subject-anchor table, regenerated from `tools/subject_anchor.py` (rc=0) rather than a listing.
- The `opencrabs-dev` factory path, read from `registry/factories/opencrabs-dev.json` — which
  falsified a 20-round carried claim (scorecard 2).

### Two errors of this round, recorded

1. **The `opencrabs.db` horizon was first computed as `bytes / (bytes/day) / 86400`**, which
   printed `0.0004 d`. Correct form is `remaining / rate_per_day` = **31.0433 d**.
2. **The fleet-score ordinal regex matched 2 of 60 artifacts** because older files write
   `350 / 456 = 76.7544 %` without the bold markers. Corrected pattern
   `(\d{3})\s*/\s*456\s*=\s*([\d.]+)\s*%` matches 60 of 60, and the ordinal was then confirmed by
   reading 11-09 = 31st, 11-10 = 32nd, 11-11 = 33rd, so today is the **34th**.

### Two traps avoided

- **`systemctl show opencrabs.service` at system scope returns `NRestarts=0`,
  `MemoryMax=infinity`, `OOMPolicy=` empty.** The unit is a `--user` unit; the system-scope read
  is a false negative against a nonexistent unit, and taking it at face value would have reported
  a 1 GiB cap as unlimited.
- **`cron_job_runs.completed_at` is TEXT ISO, not a unix timestamp.** `date(completed_at,
  'unixepoch')` silently returns zero rows — which reads as "no runs today" rather than "wrong
  predicate". `substr(completed_at,1,10)=?` returns 30 runs, 30 success.
