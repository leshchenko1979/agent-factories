## 7. Defect found this run — a live instance of OPEN #366

**This lane was woken twice by one cron tick.** `messages` seq 29 @ 06:03:37 and seq 31 @
06:09:37 are **byte-identical** (222 B). First-hand log chain:

| Time (UTC) | Receipt |
|---|---|
| 06:01:32 | cron `factory-measurement-daily` fires; run `0365109a` = `success`, content `Dispatched.` |
| 06:03:25.738 | `quiet_delivery.rs:200` `quiet batch release: delivered id=b8a753a3…` |
| 06:09:30.769 | `restart_recovery.rs:161` `Delivered 1 parked restart report(s)` to the same session |
| 06:09:33.520 | `cli/ui.rs:2162` `OpenCrabs daemon started` |

One enqueue, **two deliveries** — the daemon restarted mid-turn and restart recovery
re-delivered an entry already delivered. The same mechanism fired on **09-18** (seq 15 @
10:01:17 and seq 17 @ 10:14:54, both 3306 B — the #32 work request, with
`restart_recovery.rs:161` at 10:14:54).

**Already filed: `leshchenko1979/opencrabs` #366 (OPEN, zero comments)** — *"restart recovery
re-delivers a parked turn at every boot: pending_requests rows are not cleared on delivery,
so one body lands 5x and the work re-executes."* The source comment predicts it: *"a failed
clear costs a duplicate after the next restart, never a lost report (#73)."*
**Action: attach these receipts to #366. Not a new issue.**

*Method note:* a first `group by content` scan reported three duplicate pairs (9/13, 15/17,
29/31). **9/13 is a false positive** — the daily tick's prompt text is fixed, so two
different days produce identical bytes. A count by pattern is not a count of items.
